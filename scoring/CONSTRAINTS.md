# Scientist Constraints

## Data
Use only `data/smartposer_synthetic` generated by `data/synthetic_smartposer.py` for the benchmark scores. Do not train on the held-out test windows, and do not replace the test split with easier generated data.

## Model Scale
The parameter count must be reported in `param_count_k`. Improvements should stay in the same small-model regime as the paper; increasing the model by more than 2x over SmartPoser's 46.4k parameters violates the constraint.

## Inputs
Use only the provided sensor feature streams: raw phone-watch distance, phone/watch orientations, and phone/watch accelerations. Do not add ground-truth joint coordinates, future labels, or external pose measurements as model inputs.

## Compliance Checklist
- [ ] Training uses only the generated training windows.
- [ ] Evaluation uses the fixed generated test windows.
- [ ] Model parameter count is reported and is not more than 92.8k.
- [ ] Inputs are limited to the provided sensor features.
